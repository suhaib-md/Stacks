## 1. Architecture overview

```
┌─────────────────────────────────────────────────────┐
│  Browser (PWA — phone + laptop)                     │
│  Next.js App Router · React Server Components       │
│  Client islands: scanner, confirm sheet, color extract│
│  Service worker (Serwist): app shell + list cache   │
└────────────────────┬────────────────────────────────┘
                     │ HTTPS
┌────────────────────▼────────────────────────────────┐
│  Cloudflare Workers (Next.js via @opennextjs/cloudflare)│
│  · Route handlers (/api/*)                          │
│  · Middleware: session cookie gate                  │
│  · Metadata lookup + merge + cache                  │
└──────┬──────────────────────────┬───────────────────┘
       │ D1 binding               │ fetch (outbound)
┌──────▼────────────┐   ┌─────────▼──────────────────┐
│  Cloudflare D1    │   │  Open Library API (primary)│
│  SQLite · Drizzle │   │  Google Books API (fallback)│
│  books, lookup_   │   └────────────────────────────┘
│  cache, settings  │
└───────────────────┘
```

Single Worker, single database, no queues, no background jobs. Every write is a synchronous request against D1.

## 2. Stack decisions

| Layer | Choice | Rationale |
|---|---|---|
| Framework | Next.js (App Router, TypeScript) | Server components keep the library list off the client bundle; route handlers double as the API |
| Adapter | `@opennextjs/cloudflare` | Fuller Next.js feature support than `next-on-pages`; actively maintained path for Workers |
| Hosting | Cloudflare Workers | Free tier, edge, HTTPS by default (camera requires it) |
| Database | Cloudflare D1 | SQLite; a single-user book library is trivially within limits |
| ORM | Drizzle ORM + drizzle-kit | Typed schema, SQL-shaped, first-class D1 support, versioned migrations |
| Styling | Tailwind CSS | Utility-first; design tokens as CSS variables for theming |
| Fonts | Fraunces or Lora (display) + system sans (body) | Paper-and-ink character without a heavy font payload |
| Scanner | Native `BarcodeDetector`, `html5-qrcode` fallback | Native is fast and battery-cheap where present (Android Chrome); ZXing-based fallback covers the rest |
| Metadata | Open Library (primary), Google Books (fallback/enrichment) | Both free; Open Library needs no key |
| Covers | Remote URLs only | No image hosting, no storage cost, no upload pipeline |
| Auth | Signed session cookie from a passphrase | Single user; anything heavier is theater |
| PWA | Web manifest + Serwist service worker | Installability and an offline library list |

### Decisions deliberately not taken

- **No R2 / image hosting.** Cover URLs are stored, not images. Accepted risk: link rot (see PRD §9).
- **No join tables for authors/tags.** JSON-encoded text columns. Single-user scale makes normalization pure cost. Revisit only if a query genuinely needs it.
- **No client-side state manager.** Server components plus URL search params hold the state. Filters live in the URL, which makes views shareable and back-button-correct for free.
- **No offline write queue.** Sync conflict handling is disproportionate to the benefit. Writes require network; reads do not.

## 3. Environment and configuration

### Bindings (`wrangler.jsonc`)

| Binding | Type | Purpose |
|---|---|---|
| `DB` | D1 database | Primary datastore |
| `SESSION_SECRET` | Secret | HMAC key for the session cookie |
| `APP_PASSPHRASE` | Secret | The single access passphrase (stored hashed) |
| `GOOGLE_BOOKS_KEY` | Secret (optional) | Raises Google Books quota; app must work without it |

Local development uses `wrangler dev` with a local D1 instance and a `.dev.vars` file. `.dev.vars` and `.env*` are gitignored; secrets are set via `wrangler secret put` for production.

## 4. Data layer

Full schema lives in [backend-schema.md](backend-schema.md). Technical contract summary:

- Three tables: `books`, `lookup_cache`, `settings`.
- All timestamps are ISO-8601 strings in UTC (SQLite has no native date type; text sorts correctly and survives CSV export unambiguously).
- `authors` and `tags` are JSON-encoded arrays stored as text. Access always goes through typed helpers — never raw `JSON.parse` at call sites.
- Migrations are generated by `drizzle-kit generate` and applied with `wrangler d1 migrations apply`, locally first, then remote. Migrations are committed and never edited after being applied to production.

## 5. API contract

All routes are Next.js route handlers under `app/api/`. All responses are JSON. Errors use the shape:

```ts
{ error: { code: string, message: string, details?: unknown } }
```

with appropriate HTTP status. Codes are stable strings (`NOT_FOUND`, `DUPLICATE_ISBN`, `INVALID_ISBN`, `UPSTREAM_TIMEOUT`, `UNAUTHORIZED`, `VALIDATION_FAILED`).

### 5.1 Lookup

#### `GET /api/lookup/isbn/:isbn`
Normalizes the ISBN, checks `lookup_cache`, then queries providers.

- **200** → `BookMetadata`
- **404** → `NOT_FOUND` when neither provider has the ISBN (still cached as a negative result with a short TTL)
- **400** → `INVALID_ISBN` when the checksum fails

Merge strategy: Open Library is authoritative for publisher, page count, and physical/publication data. Google Books fills description, categories, and cover when Open Library lacks them. Non-empty always beats empty; neither provider overwrites a field the other already populated with real data.

#### `GET /api/lookup/search?q=&limit=`
Google Books is primary here — its relevance ranking for free-text title/author queries is materially better than Open Library's. Open Library is the fallback if Google fails or is throttled. Returns up to 10 `BookMetadata` records.

### 5.2 Books

| Route | Method | Behavior |
|---|---|---|
| `/api/books` | GET | Query params: `q`, `status`, `genre`, `format`, `sort`, `order`, `page`, `perPage`. Returns `{ items, total, page, perPage }`. |
| `/api/books` | POST | Creates. Exact `isbn13` match → **409 `DUPLICATE_ISBN`** with the existing book's id. Fuzzy title+author match → created, with `warnings: [{ code: 'POSSIBLE_DUPLICATE', bookId }]` in the response. |
| `/api/books/:id` | GET | Single book. |
| `/api/books/:id` | PATCH | Partial update. Applies status-transition side effects (§6). |
| `/api/books/:id` | DELETE | Hard delete. |
| `/api/books/bulk` | PATCH | `{ ids: string[], patch: {...} }` — applied in one D1 batch. |
| `/api/export/csv` | GET | Streams `text/csv` with a `Content-Disposition` attachment header. |

### 5.3 Shared type

```ts
type BookMetadata = {
  isbn13: string | null;
  isbn10: string | null;
  title: string;
  subtitle: string | null;
  authors: string[];
  publisher: string | null;
  publishedYear: number | null;
  pageCount: number | null;
  description: string | null;
  coverUrl: string | null;
  categories: string[];
  language: string | null;
  source: 'openlibrary' | 'googlebooks' | 'merged' | 'manual';
};
```

## 6. Business rules enforced server-side

These are applied in the PATCH handler, not in the UI, so they hold regardless of client:

1. `read_status` → `reading`: set `started_at` to now if currently null.
2. `read_status` → `finished`: set `finished_at` to now if currently null; if `page_count` is known, set `current_page = page_count`.
3. `read_status` → `unread`: clear `current_page` to 0. Dates are left alone (deliberate — an accidental status click shouldn't destroy history).
4. `rating` must be null or an integer 1–5.
5. `current_page` is clamped to `[0, page_count]` when `page_count` is known.
6. `updated_at` is set on every write. Never trusted from the client.
7. `isbn13` uniqueness is enforced by a database constraint, not only by the pre-check — the check is for a good error message, the constraint is for correctness.

## 7. External API integration

### Open Library
- ISBN: `https://openlibrary.org/api/books?bibkeys=ISBN:{isbn}&format=json&jscmd=data`
- Covers: `https://covers.openlibrary.org/b/isbn/{isbn}-L.jpg`
- No key. Send a descriptive `User-Agent`. Treat any non-200 as a miss, never as a fatal error.

### Google Books
- `https://www.googleapis.com/books/v1/volumes?q=isbn:{isbn}` and `?q={free text}`
- Key optional via `GOOGLE_BOOKS_KEY`. Quota-limited when keyless — this is why it is the fallback, not the primary, for ISBN lookups.

### Resilience rules
- 4-second `AbortController` timeout per provider.
- Providers are queried in sequence for ISBN (Open Library, then Google Books only if the result is thin), and failures degrade rather than throw.
- Every outcome, including "not found", is written to `lookup_cache`. Negative results carry a shorter TTL (7 days) than positive ones (indefinite) so a book that gets indexed later is eventually picked up.
- No retries. A failed lookup falls through to the manual path, which is faster than waiting.

## 8. Barcode scanning

Runtime feature detection, in order:

1. `'BarcodeDetector' in window` and `EAN-13` in `getSupportedFormats()` → native path.
2. Otherwise dynamically import `html5-qrcode` — kept out of the main bundle so devices with native support never download it.
3. If camera permission is denied or unavailable → manual ISBN input, with the reason shown plainly.

Detection handling:
- Debounce: ignore the same code within 2500 ms of the previous detection (cameras fire many frames per second on one barcode).
- Validate the ISBN checksum before firing a lookup; reject non-book EAN-13 codes silently and keep scanning.
- Feedback on accepted read: short beep plus `navigator.vibrate(50)` where supported.
- Camera stream is explicitly stopped on unmount and on route change. A leaked stream keeps the phone's camera light on and drains battery — treat it as a bug.

## 9. Client/server split

- **Server components:** library grid and list, book detail, settings. Data is fetched directly through Drizzle — no client fetch waterfall for initial render.
- **Client components:** scanner, confirm bottom sheet, filter/sort controls, page-progress widget, rating stars, notes editor, bulk-select toolbar, dominant-color extraction.
- **Mutations:** Server Actions for form-shaped writes (edit, notes, rating); route handlers for the scan/confirm path and anything the service worker or an external tool might call.
- Filters and sort live in URL search params so navigation and back-button behavior are correct without extra state.

## 10. Dominant color extraction

Cover accent colors are computed on the client, once, and cached to the row:

1. On first render of a book detail page, if `cover_color` is null, load the cover into a canvas (cover host must allow CORS; if it doesn't, skip and use the default accent).
2. Downsample to ~32×32, bucket pixels, discard near-white/near-black, pick the most saturated frequent bucket.
3. Clamp lightness into a band that stays legible against both themes.
4. PATCH the hex to `cover_color`. Never recompute for that book again.

Failure is non-fatal in every case — the page falls back to the neutral theme accent.

## 11. Performance budget

| Metric | Target |
|---|---|
| Grid first contentful paint (300 books) | < 1 s |
| Barcode detected → confirm sheet visible | < 1.5 s |
| Cached ISBN lookup | < 100 ms |
| App JS on the library route, above framework baseline | < 40 KB gzipped |

### The JS budget was wrong, and here is the measurement

This originally read "< 150 KB gzipped on the library route". That target is **not achievable on this stack** and was written before anything was measured.

Measured on a production build (Phase 5):

| Route | Eager JS (gzipped) | Notes |
|---|---|---|
| `/login` | **169 KB** | One input and a button. This is the floor. |
| `/settings` | 174 KB | Theme toggle, install prompt, sign-out |
| `/` | 193 KB | Cover grid, toolbar, currently-reading, bulk edit |

React 19 plus the Next 16 App Router runtime costs **169 KB before a single line of application code**. A 150 KB total was never reachable without abandoning the framework, which is not a trade worth making for a single-user catalogue.

So the budget is now expressed against the baseline: **the library route may add at most 40 KB over `/login`.** It currently adds 24 KB for the entire browsing experience, which is the number actually worth defending.

Getting there took real work — moving the bulk-edit dialogs and the progress sheet behind `next/dynamic` cut the library route from 258 KB to 193 KB, because none of it is needed until you long-press a cover or tap a progress bar.

Techniques: server-rendered lists, `loading="lazy"` plus explicit dimensions on cover images (prevents layout shift), dynamic import of the scanner fallback, pagination at 60 per page with virtualization only if the library exceeds ~300 books.

## 12. Security

- Middleware gates every route except `/login`, `/api/auth/*`, and static assets.
- Session cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, signed with HMAC-SHA256 over `SESSION_SECRET`, ~30-day expiry.
- Passphrase is compared against a stored hash using a constant-time comparison. Login attempts are rate-limited to blunt brute force.
- No user-generated HTML is rendered; descriptions from external APIs are rendered as text, not HTML.
- Only Open Library and Google Books hosts are contacted outbound.

## 13. Testing

- **Unit:** ISBN validation and 10↔13 conversion (a table of real ISBNs including X check digits), provider response mappers against recorded fixtures, the merge function, CSV escaping (commas, quotes, and newlines inside titles and notes).
- **Integration:** route handlers against a local D1 — dedup path, status-transition side effects, filter/sort query building.
- **Manual QA matrix:** scanner on Android Chrome, iOS Safari, and desktop webcam; offline library list; install prompt; CSV opened in Sheets and Excel.

Full automated coverage of UI is out of scope for v1 — a single-user app with a fast feedback loop does not earn it.

## 14. Deployment

- Cloudflare Git integration builds and deploys on push to `main`.
- Migrations are applied deliberately, not as part of the automatic build: `wrangler d1 migrations apply stacks-db --local` first, then `--remote` once verified.
- Rollback is a redeploy of the previous commit. Because migrations are additive, a code rollback does not require a schema rollback.
